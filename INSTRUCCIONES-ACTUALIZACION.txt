TARJETA JOVEN ELOTA - GUÍA PASO A PASO
========================================

MEJORAS V10
----------
- Las fotografías ahora se convierten automáticamente a WebP, se redimensionan
  según su uso y ajustan su calidad de manera progresiva para ocupar lo mínimo
  posible sin degradarlas innecesariamente.
- Metas aproximadas: foto juvenil 160 KB, documento fotográfico 500 KB, logo de
  negocio 150 KB y fotografía de fachada 300 KB. El resultado puede variar de
  acuerdo con la imagen original.
- La conversión mediante el navegador elimina metadatos innecesarios de las
  fotografías. Los PDF no se recomprimen y conservan el límite de 1.5 MB.
- Al sustituir una foto de perfil, logo, menú o promoción, el archivo anterior
  se elimina de Storage para no acumular copias que ya no se utilizan.
- Al eliminar un joven o negocio desde el panel también se retiran sus imágenes
  asociadas de Storage.
- El documento de identidad del joven y la evidencia de fachada del negocio son
  temporales: se eliminan automáticamente al aprobar o rechazar la solicitud.
- La foto de perfil juvenil y el logo del negocio sólo se conservan cuando la
  solicitud es aprobada, porque forman parte de la tarjeta y del directorio.
- El aviso de privacidad y la aceptación del registro explican expresamente el
  uso temporal y la eliminación de las evidencias de validación.
- Se eliminó el naranja de la interfaz y se sustituyó por una paleta neutra de
  gris pizarra, blanco suave, verde petróleo e índigo tenue.
- Los logotipos oficiales se conservan intactos; su presencia decorativa se
  redujo para mantener una interfaz limpia, cómoda y fácil de comprender.
- El registro evita enviar archivos que superen el límite de las funciones de
  Vercel y avisa cuando un PDF debe reducirse a menos de 1.5 MB.
- Las fotografías siguen comprimiéndose automáticamente antes del envío.
- El registro funciona desde el dominio principal o una URL de despliegue de
  Vercel cuando la solicitud se realiza desde la misma página.
- Si Firebase Admin está incompleto, el sistema informa qué credencial revisar
  en lugar de mostrar solamente "No fue posible guardar la solicitud".
- Los tamaños críticos de los logotipos y las animaciones principales también
  se incluyen directamente en el documento. Esto evita diferencias visuales
  entre localhost y el CSS optimizado que publica Vercel.
- Se añadieron límites mínimos y máximos al logotipo de encabezado para impedir
  que una regla externa o un archivo retrasado pueda ampliarlo.
- El panel de misiones siempre aparece por encima de la tarjeta digital, el
  escáner, las ventanas y la navegación; ya no queda escondido detrás.
- La identidad visual usa tonos sobrios para que los colores completos de los
  logotipos oficiales destaquen sin competir con botones, fondos o formularios.
- Los logotipos forman parte de la experiencia mediante halos suaves, marcas de
  agua y movimiento ligero en portada, tarjeta y portal de negocios.
- Se rediseñaron encabezados, paneles principales, accesos y navegación inferior
  para que la aplicación se sienta más fresca tanto en celular como en PC.
- Las animaciones usan solamente CSS con opacidad y transformaciones, respetan
  la opción de movimiento reducido y no requieren una librería adicional.
- Se eliminó un patrón de 50 elementos repetidos de la tarjeta y se sustituyó
  por una marca de agua WebP y cinco acentos ligeros para reducir trabajo visual.
- La sesión se conserva al cerrar y volver a abrir una pestaña.
- El lector QR usa cámara trasera, guía animada y una consulta compatible con
  las reglas de seguridad: el negocio solo consulta sus propias visitas.
- La captura manual TJE fue retirada para conservar la experiencia de escaneo.
- Las misiones juveniles abren directamente QR, beneficios, aliados o empleos.
- Las misiones de negocio abren perfil, promociones, vacantes o escáner.
- La portada fue rediseñada con una experiencia más moderna y juvenil.
- Se agregó una tipografía más fresca y animaciones CSS ligeras sin librerías.
- Al completar las misiones se desbloquean insignias, aparece una celebración y
  comienza una meta continua basada en visitas o validaciones reales.
- En computadora, las tarjetas y rutas aprovechan dos columnas; en celular se
  conservan botones grandes, desplazamiento táctil y una sola columna.
- Los fondos usan los logotipos WebP comprimidos con movimiento CSS muy ligero.
- El enlace de activación abre una página propia para crear la contraseña.
- Los correos institucionales muestran los logotipos oficiales de IMJU y del
  Ayuntamiento de Elota.
- Las misiones ya no ocupan un bloque grande: se muestran como una barra compacta.
- Al tocar la barra, las misiones se abren en una hoja inferior en celular y en
  un panel centrado en computadora.
- Cada nueva misión juvenil muestra una notificación breve de recompensa.
- Las insignias, metas y celebraciones se conservan sin saturar la pantalla.
- Los portales recuperan una columna central proporcionada tanto en móvil como
  en escritorio, priorizando QR, beneficios y escáner.

La cámara funciona en http://localhost:3000 y en sitios HTTPS como Vercel. Si
abres desde un celular usando una dirección local http://192.168..., el navegador
puede bloquear la cámara; prueba el escáner en Vercel mediante HTTPS.

IMPORTANTE
----------
Esta versión usa Firebase Authentication para jóvenes y negocios. Las
contraseñas ya no se guardan ni se muestran en Firestore.

Como los datos actuales son de prueba, elimina jóvenes, negocios, tarjetas,
visitas, promociones y empleos de prueba antes de comenzar. Conserva la
colección administradores y tu usuario Master de Firebase Authentication.
También elimina de Authentication las cuentas de jóvenes y negocios de prueba.

1. ABRIR EN VISUAL STUDIO CODE
------------------------------
Descomprime el ZIP y usa Archivo > Abrir carpeta. En Terminal > Nueva terminal:

  npm install

2. CREAR .env.local
-------------------
Copia .env.example y nombra la copia .env.local. Completa las seis variables
NEXT_PUBLIC_FIREBASE_ con los datos de Firebase > Configuración del proyecto >
General > Tus apps > Aplicación web.

No subas .env.local a GitHub.

3. ACTIVAR INICIO DE SESIÓN
---------------------------
Firebase > Authentication > Sign-in method > Correo electrónico/contraseña.
Activa la primera opción y guarda.

En Authentication > Settings > Authorized domains confirma:

  localhost
  tarjeta-imju-elota.vercel.app

Si tu dominio de Vercel es diferente, agrega exactamente el dominio real.

4. CUENTA DE SERVICIO PRIVADA
-----------------------------
Firebase > Configuración del proyecto > Cuentas de servicio > Generar nueva
clave privada. Se descargará un JSON. NO lo copies al proyecto ni a GitHub.

Del JSON usa en .env.local y en Vercel:

  FIREBASE_ADMIN_PROJECT_ID       = project_id
  FIREBASE_ADMIN_CLIENT_EMAIL     = client_email
  FIREBASE_ADMIN_PRIVATE_KEY      = private_key completa
  FIREBASE_ADMIN_STORAGE_BUCKET   = igual a NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET

La llave puede conservar los signos \n o usar saltos de línea reales.
En Vercel, no agregues comillas al inicio o al final del valor. Selecciona los
entornos Production y Preview y realiza un Redeploy después de guardar.

5. CORREO GMAIL
---------------
En tarjetaimjuelota@gmail.com activa verificación en dos pasos y crea una
Contraseña de aplicación para Correo. Después configura:

  EMAIL_USER=tarjetaimjuelota@gmail.com
  EMAIL_APP_PASSWORD=la_clave_de_16_caracteres
  APP_URL=http://localhost:3000

EMAIL_APP_PASSWORD no es la contraseña normal de Gmail.

6. PUBLICAR LAS REGLAS
----------------------
En Firebase > Firestore Database > Reglas, copia firestore.rules y publica.
En Firebase > Storage > Reglas, copia storage.rules y publica.

No omitas la publicación de storage.rules en esta versión: contiene el nuevo
límite de 750 KB por imagen para impedir cargas innecesariamente pesadas.

7. PROBAR LOCALMENTE
--------------------
En la terminal:

  npm run build
  npm run dev

Abre http://localhost:3000 y prueba en orden:

  1) Registrar un joven en /login.
  2) Aprobarlo en /panel-imju-elota.
  3) Abrir su correo y crear la contraseña.
  4) Entrar como joven y mostrar su QR.
  5) Registrar y aprobar un negocio.
  6) Abrir su correo, crear contraseña y entrar al portal.
  7) Escanear el QR y registrar una visita.
  8) Confirmar que aumente el progreso del joven.

El documento probatorio y la evidencia se borran al aprobar o rechazar. La foto
de perfil y el logo sí se conservan.

Para verificar la eliminación, revisa Firebase > Storage después de aprobar o
rechazar: el documento o evidencia ya no debe existir. En una aprobación sí
deben permanecer la foto de perfil o el logo necesarios para el servicio.

8. SUBIR A GITHUB DESDE VS CODE
-------------------------------
Ejecuta:

  git status
  git add .
  git commit -m "V10 compresion inteligente y privacidad"
  git push origin main

En cambios futuros repite git add, git commit y git push. Vercel desplegará cada
push automáticamente; no necesitas subir archivos manualmente en GitHub.

9. VARIABLES EN VERCEL
----------------------
Vercel > proyecto > Settings > Environment Variables. Agrega todas las variables
de .env.example para Production, Preview y Development. En producción usa:

  APP_URL=https://tarjeta-imju-elota.vercel.app

Sin diagonal al final. Si la URL real es otra, usa exactamente esa.

FIREBASE_ADMIN_, EMAIL_APP_PASSWORD y la llave privada son secretos. Nunca deben
comenzar con NEXT_PUBLIC_. Después abre Deployments y elige Redeploy.

10. ACCESOS
-----------
Al aprobar, el sistema crea la cuenta de Authentication, genera el QR cuando
corresponde, borra la evidencia y envía un enlace para definir la contraseña.
Nunca guarda la contraseña en Firestore.

En los directorios del panel, el botón Acceso reenvía el enlace si la persona no
recibió el primero.

Después de publicar esta versión, reenvía el acceso desde el panel para probar la nueva
pantalla de contraseña. Los enlaces generados antes de publicar pueden conservar
la pantalla anterior de Firebase.
